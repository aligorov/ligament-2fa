# Отчёт: модель лицензирования Ligament

Дата: 2026-09-06 · Статус: **предложение на согласование** (реализация — после одобрения)
Основано на агентном исследовании best practices (сентябрь 2026, источники в сносках).

## 1. Контекст и рамки

Self-hosted продукт: один Go-бинарник + PostgreSQL (docker-compose), работает в
приватных сетях, **часто без интернета**. Продажа B2B: per-user-per-year
подписка + perpetual (бессрочная). Нужны: обновления, деактивация, демо-доступ.

Главный вывод исследования: для «одного бинарника в закрытой сети» рыночная
норма — **оффлайн подписанный license-файл**, загружаемый через web-UI.
Activation-сервер (keygen.sh, Cryptolens, LicenseSpring) — overkill: внешняя
точка доверия или лишний контейнер у клиента, а интернет не гарантирован.

## 2. Сравнение вариантов дистрибуции лицензий

| | Оффлайн файл (Ed25519) | License-ключ | Activation-сервер |
|---|---|---|---|
| Работает без интернета | да (нативно) | да, если самоподписанный | нет / grace |
| Отзыв | expiry / CRL-блоб | то же | мгновенный |
| Rich-метаданные (лимиты, даты) | да | плохо | да |
| Нагрузка на вендора | генератор-CLI | генератор | сервис+БД+аптайм |
| Цена ошибки у клиента | нет | нет | «всё упало» на площадке |

Примеры: Grafana Enterprise (токен + call-home раз в 24 ч), КриптоПро
(perpetual-серийник, вводится локально, интернет не нужен, демо 90 дней),
JetBrains (подписка с perpetual fallback), Atlassian Server (perpetual +
12 мес maintenance), Invoice Ninja (self-hosted: ключ white-label $30/год),
MinIO (SUBNET — и бэклэш сообщества за обрезание UI: урок — не калечить
бесплатную версию), HashiCorp MPL→BUSL (урок: форки).

## 3. Рекомендуемая схема для Ligament

### 3.1 Формат лицензии — оффлайн FILE

Канонический JSON-payload + **Ed25519-подпись** (алгоритм жёстко зафиксирован
в коде, без JWT-зависимостей и alg-confusion), base64 в обёртке:

```
-----BEGIN LIGAMENT LICENSE-----
<base64(payload)>.<base64(sig)>
-----END LIGAMENT LICENSE-----
```

Поля payload: `lic_id` (UUID — для отзыва/реестра), `customer` (для UI),
`plan`: `subscription` | `perpetual`, `user_limit`, `issued_at`,
`expires_at` (только subscription; perpetual → null), `maintenance_expires`
(до какой даты доступны обновления), `features` (edition-флаги), `kid`
(ID ключа подписи), `notes`.

Публичные ключи (2–3, ротация по `kid`) зашиты в бинарник; приватные —
только в офлайн-хранилище вендора. Подделка невозможна без приватного ключа.

### 3.2 Тарифы

- **Подписка**: X ₽/пользователь/год; лицензия `expires_at ≤ 13 мес.`
  (в оффлайне перевыпуск раз в год по оплате; онлайн-refresh опционален).
- **Perpetual**: единоразово; `expires_at=null`, обновления до
  `maintenance_expires` (12 мес., продлеваемо). Вечное право на версии,
  выпущенные до этой даты (классический version pinning — Atlassian/Avid).
- **Freemium**: без лицензии — до **5 активных пользователей навсегда**
  (воронка роста для малых команд).
- **Демо**: встроенный **30 дней full-featured** без обращения к вендору —
  старт trial персистится в Postgres (сбрасывается только с БД); как демо
  КриптоПро. Без телеметрии.

### 3.3 Подсчёт и enforcement мест

Счётчик = активные (не disabled) пользователи. Enforcement по практике
GitLab/Directus, с поправкой на специфику 2FA — **никогда не выключаем вход
существующим пользователям** (иначе организация теряет доступ ко всему):

1. Достижение лимита → баннер в админке + событие в audit.
2. Grace 30 дней (создание сверх лимита — с предупреждением).
3. Далее — запрет **создания/включения** пользователей сверх лимита.
   RADIUS/REST-аутентификация существующих не блокируется никогда.

### 3.4 Обновления (гейт)

`build_date` вшивается в бинарник (`-ldflags -X`). При старте:
`build_date <= maintenance_expires`, иначе отказ старта с внятным сообщением
«откатитесь на версию X.Y или продлите maintenance». Публичные docker-теги
остаются публичными — «утёкший» образ без валидной лицензии бесполезен.
UI явно разделяет «лицензия действует» и «обновления доступны до» (урок
Reddit-жалоб на «вечные лицензии, которые истекают»).

### 3.5 Деактивация/отзыв

- Subscription: сам гаснет по `expires_at` (+ опциональный grace 5 дней).
- Досрочный отзыв: подписанный **CRL-блоб** (`lic_id` + `revoked_at`),
  который админ загружает на страницу лицензии вместе с новой лицензией
  или отдельно; проверка при старте и раз в час.
- Perpetual отзыв технически не возможен (и не обещается) — только юридишески.

### 3.6 Отдельный licensing-контейнер — НЕТ

Валидатор встраивается в бинарник (проверка Ed25519 — десятки строк Go),
кэш результата, re-check раз в час и при загрузке страницы «Лицензия».
Отдельный контейнер = лишний сервис/точка отказа в compose клиента; нужен
только для floating-активаций на много машин — не наш случай.

### 3.7 Admin-UI и CLI

- Страница **«Лицензия»** (админ-сайдбар): drag-n-drop/вставка файла; статус:
  план, X/Y пользователей, демо до, обновления до, отпечаток lic_id; кнопка
  «запросить/продлить» (mailto); все действия в audit log.
- Вендорский CLI (`ligament-license` в закрытом репо): генерация/перевыпуск
  лицензий и CRL приватным ключом; реестр lic_id. Внешние платформы
  (keygen/Cryptolens) — только если появятся сотни сделок в месяц.

### 3.8 Чего НЕ строим (осознанно)

- **Anti-tamper/DRM**: Go-бинарник патчится, MAC подделывается —
  лицензирование это юридический барьер + удобство оплаты, не защита от
  кракера (consensus r/selfhosted, Security.SE).
- Обфускации, обязательного phone-home, привязки к железу (только мягкое
  информационное поле `instance_hint`).
- Не режем community-функциональность в бесплатном режиме сверх лимита
  пользователей (урок MinIO/Directus — сообщество уходит).

## 4. Реализация в коде (после согласования, ~1 задача агенту)

1. `internal/license/`: parse+verify (Ed25519, зашитые ключи), payload-модель,
   state (free/trial/licensed), лимит-проверка на UserCreate/UserUpdate(enabled),
   build-date gate в main.
2. Таблица `license_state` (или ключи в settings): загруженная лицензия,
   trial_start, CRL.
3. Admin API: GET/PUT /api/v1/admin/license; middleware-флаг для создания
   юзеров; баннер в base-шаблоне; страница в UI.
4. `-ldflags` build date в Makefile/Dockerfile + релизный процесс.
5. Вендорский CLI-генератор — отдельный приватный модуль (общий пакет
   payload-формата).
6. Тесты: подпись/подделка, истечение, лимиты (grace), CRL, демо-персистентность.

## 5. Юридический скелет (EULA, для юриста)

Единый EULA + два приложения (subscription/perpetual): non-exclusive,
non-transferable grant; version pinning по maintenance_expires; refund —
14 дней (subscription) / без refund (perpetual со скидкой); audit-clause не
чаще 1 раза в 12 мес. по данным admin-UI («число активных пользователей»);
warranty disclaimer, liability cap, «лицензия ≠ SLA».
Оплата РФ: счёт/ЮKassa/СБП, лицензия файлом на email (санкции на файл
не действуют); крипта — только с учётом правил ВК/ФНС для юрлиц.
